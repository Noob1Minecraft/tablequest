Для печатного QR используйте **https://tablequest-pink.vercel.app/?table=12** (замените номер стола). Это постоянный production-домен проекта, а не временный URL отдельного деплоя. Генератор в меню «…» принимает эту ссылку на любой из площадок; на Vercel текущий адрес подставляется автоматически. Параметры demo удаляются из предлагаемого QR-адреса.

Все три площадки подключены к `Noob1Minecraft/tablequest`, ветка `main`. Данные браузера и офлайн-кеш отдельны для каждого домена: прогресс между площадками автоматически не переносится.

TableQuest — мобильное веб-приложение/PWA для живого общения в кафе: один QR-код, один телефон на компанию, короткие задания и время вместе. Без аккаунтов, API-ключей и backend.

## TAMOS validation

Контекст компании действительно влияет на набор: из 18 существующих заданий в каждом режиме два общих (`any`), остальные имеют подходящие категории `friends`, `couple`, `family`, `celebration`. Сначала выбираются случайные контекстные задания, затем общие; 3/5 уникальных заданий доступны для каждого допустимого сочетания. Старое значение `party` в сохранениях соответствует `celebration`. Демо по-прежнему использует фиксированный набор.

Основной вопрос: «После TableQuest вам стало легче общаться?» (RU/KK/EN). Сохраняются `answer` (yes/little/no), необязательный `comment` («Что помешало?»), `repeat`, `mode`, `company`, `locale`, `tableId`, `date` и `metric=connection-v1`. CSV содержит все эти поля. Старые ответы сохраняют метрику `legacy-evening`, без выдуманного ответа на новый вопрос. Это субъективный отзыв, не доказательство возвращаемости или бизнес-эффекта.

Локальные настройки: `src/config/restaurant.ts` — имя, необязательный логотип (путь относительно public/), переключатель момента, заголовок, текст и название награды на трёх языках. По умолчанию момент выключен; `?demo=true&business=true` показывает его в recap после трёх раундов. Можно включить через config для обычной игры. На сессию только одна карточка и один сохраняемый демо-запрос; reload не создаёт повторный запрос. Это DEMO, без POS и отправки персоналу. Панель управления конфигурацией не нужна.

Дизайн **After Hours**: угольные поверхности, тёплый свет, акценты шампань и спокойная типографика. [Референсы и дизайн-система](docs/DESIGN.md) · [Проверки и ограничения](docs/QA.md).

Для презентации: [Fun demo](https://noob1minecraft.github.io/tablequest/?demo=true) · [Team Battle demo](https://noob1minecraft.github.io/tablequest/?demo=true&mode=battle). Сразу открывается первое задание: 4 друга, 5 минут, 3 раунда. Демо сохраняется отдельно от обычной игры.

## Hospitality prototype

- [Business demo](https://tablequest-pink.vercel.app/?demo=true&business=true&table=12&venue=demo): 4 друга, Fun, 3 заданных раунда, затем один **Restaurant Moment** в recap. `mode=battle` включает командный вариант. В обычной игре модуль включается только через `business=true` или `venue=demo`; по умолчанию его нет.
- Пример предложения и тексты задаются локальным restaurant config. Все предложения демонстрационные. Кнопка вызывает `MockPosAdapter`, сохраняет факт демо-запроса локально и больше не предлагает повторить его в этой сессии, в том числе после reload. Ничего не отправляется официанту; iiko/R-Keeper, заказ и оплата не подключены.
- В отзыве есть необязательный раскрываемый раздел: оценка 1–5, категория и комментарий до 500 символов. Обычные вопросы остаются короткими. Телефон, email и WhatsApp не собираются.
- [Локальные отзывы](https://tablequest-pink.vercel.app/?admin=true): отдельные вкладки обычных и демо-ответов, число ответов, средняя только явно поставленных оценок 1–5, категории, стол, заведение, язык, режим и время; экспорт CSV. Это **локальный прототип без авторизации**, а не защищённая админка или общая аналитика ресторана. Старые ответы «Да / Немного / Нет» не превращаются в выдуманные оценки 1–5.
- `?table=12` совместим с прежними QR; `venue` — необязательное обозначение заведения. После завершения сессии можно читать recap и оставить отзыв без использования новых модулей.

### Optional feedback webhook

Без `VITE_FEEDBACK_WEBHOOK_URL` всё работает локально. Для подключения задайте собственный публичный HTTPS endpoint в окружении сборки и пересоберите сайт. Пример переменной есть в `.env.example`. URL **виден в браузере**: private API keys, пароли и секреты в `VITE_*` не допускаются. Реальный endpoint не предоставлен и в production не настроен.

Endpoint Make, Apps Script или другой сервис должен принимать `POST` JSON, отвечать 2xx и разрешать CORS / preflight с трёх production origins. Сначала сохраняется локальная копия, затем отправляется запрос с timeout 5 секунд. При сетевой ошибке, CORS, timeout или non-2xx отзыв остаётся локально; UI честно сообщает об ошибке доставки. Автоматической повторной отправки нет. При недоступном localStorage форма сообщает о проблеме и не отправляет ответ удалённо. **Демо-ответы никогда не отправляются в webhook.**

Payload: `id`, `timestamp`, `tableId`, `venue`, `language`, `mode`, `rating` (явная оценка 1–5 либо null), `satisfaction` (0/1/2: Нет/Немного/Да), `category`, `comment`, `repeat`. Для защиты от повторов endpoint может использовать `id` сессии. Пользователь заранее видит, отправится ли ответ в подключённый сервис. Без backend нет обещания доставки, рассылки или отложенного напоминания.

Хранилища отзывов по-прежнему ограничены последними 50 ответами каждого типа. `tablequest.moments` / `tablequest.demo.moments` содержат до 50 идентификаторов завершённых демо-запросов. Эти данные также отдельны для каждого домена. Memory Capsule, настоящая POS-интеграция и контактные данные сознательно не добавлены.

## Запуск

Нужен Node.js 24; версия закреплена в `package.json`.

```sh
npm install
npm run dev
```

Откройте http://localhost:5173. Для телефона в той же Wi-Fi сети используйте Network URL, который выводит Vite. PWA требует HTTPS или localhost; на обычном HTTP по локальной сети сервис-воркер не устанавливается.

```sh
npm run build       # TypeScript + production-сборка в dist/
npm run preview     # http://localhost:4173, в том числе проверка PWA
npm test            # логика выбора, счёт, восстановление, переводы
npm run test:e2e    # браузерные сценарии, offline, адаптивность, QR
```

E2E локально использует установленный Microsoft Edge; в CI — Chromium (`npx playwright install chromium`). Перед локальным E2E нужна `npm run build`. Переменная `PLAYWRIGHT_BASE_URL` позволяет проверить уже опубликованный сайт вместо локального preview. Workflow автоматически проверяет публичный GitHub Pages после деплоя и сохраняет скриншоты на 7 дней.

### Если npm в Windows не запускается

При ошибке `Cannot find module ... AppData/Roaming/npm/.../npm-cli.js` можно использовать исправную копию npm из установленного Node.js, не меняя настройки компьютера:

```powershell
function npm { & 'C:\Program Files\nodejs\node.exe' 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' @args }
npm install
npm run dev
```

Функция действует только в текущем окне PowerShell. В ограниченном окружении задайте доступный кеш: `npm install --cache .tools/npm-cache`.

## Возможности

- RU / Қазақша / English: весь интерфейс, 18 заданий (по 6 на режим), ошибки, результаты и обратная связь.
- Определение первого поддерживаемого языка браузера и сохранение ручного выбора. Язык переключается без сброса игры.
- Компания: друзья, пара, семья или праздник; 2–8 участников; 5 или 10 минут (примерная длительность).
- Connect — вопросы и истории; Fun — импровизация и юмор; Team Battle — соревнование двух команд от 4 участников.
- 3 или 5 неповторяющихся заданий в сессии; набор подобран по режиму, контексту и размеру компании. Контекстные задания имеют приоритет перед общими (`any`).
- Именованные команды, разделение поровну, 1 очко победителю или по 1 за ничью, итоговый счёт.
- Welcome → компания → режим → задание: три основных нажатия с настройками по умолчанию. Названия команд редактируются прямо на экране режима, без обязательного дополнительного шага.
- Крупный вопрос и отдельная короткая инструкция. Спокойный экран «телефон вниз», карточка воспоминания в recap, повтор игры или смена режима с сохранением компании.
- Таймер 60/90 секунд, пауза, досрочное завершение. Сохранённый deadline учитывает сворачивание и перезагрузку страницы. После истечения времени переход выполняется по кнопке, чтобы не оборвать разговор.
- Восстановление незавершённой игры через «Продолжить игру». Валидация повреждённых сохранений, работа без доступного localStorage с уведомлением.
- Recap пройденных заданий, фактическое время с момента начала (включая паузы, минимум 1 минута), демо-награда «Легенды этого стола».
- Отзывы хранятся только на устройстве (до 50). Они **не отправляются** в ресторан или владельцу сайта.
- Устанавливаемая PWA: манифест, PNG-иконки, версионированный precache Workbox, уведомление об обновлении. Обновление не применяется автоматически посреди раунда.
- Полный игровой сценарий и три языка работают без интернета после первого успешного кеширования production-версии. При первом визите без сети загрузка невозможна.
- Генератор скачиваемого SVG QR-кода для публичной HTTPS-ссылки. Параметр `?table=12` показывает номер стола на стартовом экране.
- Адаптивность 320px–desktop, клавиатура, подписи кнопок, фокус при смене экранов, уменьшение анимации по настройке ОС.

Награда демонстрационная: реальные скидки и подарки ресторана не обещаются. Пользовательские названия команд не переводятся автоматически. Все данные и переводы входят в сборку; внешних шрифтов, аналитики и сетевого переводчика нет.

## Технологии и структура

React 19, Vite 8, TypeScript, CSS, Lucide, QRCode, vite-plugin-pwa/Workbox. Vitest и Playwright для проверок.

```text
src/
  App.tsx               # экраны и игровой сценарий
  game.ts               # выбор заданий, счёт, таймер, хранение
  session.ts            # создание обычной / демонстрационной сессии
  types.ts              # типы предметной области
  i18n/index.ts         # типизированные словари RU/KK/EN
  data/quests.json      # локальный переводимый каталог
  components/Modal.tsx   # доступные диалоги и генератор QR
  components/Welcome.tsx # ресторанный стартовый экран
  components/Teams.tsx   # команды и табло
  styles.css            # адаптивный дизайн
public/                 # иконки PWA, favicon, два размера WebP hero
docs/                   # дизайн, происхождение изображения, QA
tests/                  # логика и браузерные сценарии
.github/workflows/      # сборка, тесты и GitHub Pages
```

Ключи localStorage: `tablequest.language`, `tablequest.game`, `tablequest.demo.game`, `tablequest.feedback`, `tablequest.demo.feedback`. Для удаления локальных данных очистите хранилище сайта в браузере. Сохраняются только язык, состояние игры и локальные ответы на опрос. Демо не заменяет обычную сохранённую игру или обычные отзывы.

## Деплой и QR

### GitHub Pages

1. В репозитории откройте **Settings → Pages → Source → GitHub Actions**.
2. Запустите workflow **Deploy TableQuest to GitHub Pages** во вкладке Actions или отправьте commit в `main`.
3. После успешного деплоя сайт: `https://<username>.github.io/tablequest/`.
4. Откройте сайт → меню «…» → «QR для вашего стола» → вставьте публичную ссылку (можно добавить `?table=12`) → скачайте SVG. Распечатайте и проверьте сканирование с телефона.

Workflow уже задаёт `BASE_PATH=/tablequest/`. Если измените имя репозитория, обновите путь. Локально и для домена в корне base по умолчанию `/`.

### Vercel

Проект `tablequest` в команде Enginnerus импортирован из GitHub. `vercel.json` фиксирует Vite, `npm run build`, `dist` и повторную проверку свежести `sw.js`. В окружении Vercel задан `BASE_PATH=/`; Node.js 24 задан в `package.json`. Без переменной Vite также использует `/`. Не задавайте здесь `/tablequest/`.

### Render

Сервис `tablequest` создан как **Static Site**, не Web Service. Build: `npm install && npm run build`; Publish: `dist`; переменные `NODE_VERSION=24`, `BASE_PATH=/`, `SKIP_INSTALL_DEPS=true`. `render.yaml` сохраняет воспроизводимую конфигурацию. Существующий сервис создан напрямую, поэтому изменения Blueprint не применяются к нему автоматически: настройки сервиса меняются отдельно либо сервис переводится под управление Blueprint.

В Render также настроены HTTP Headers: `/manifest.webmanifest` → `Content-Type: application/manifest+json`; `/*` → `Cache-Control: public, max-age=0, must-revalidate, no-transform`. Это даёт manifest корректный MIME-тип и запрещает CDN преобразовывать иконки в варианты, несовместимые с precache при офлайн-запросах.

Приложение использует query-параметры и внутреннее состояние, без дополнительных URL-маршрутов; catch-all rewrite не требуется. Manifest, иконки, изображения и service worker используют base текущей площадки. GitHub Actions отдельно задаёт `BASE_PATH=/tablequest/`, поэтому root-конфигурация новых площадок не меняет GitHub Pages.

Загружайте на статический хостинг содержимое `dist/`, а не исходники. Service worker включён только в production-сборке. Предложение обновить уже открытый клиент находится во вторичном меню; обновление не прерывает раунд.
